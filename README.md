# LightGBM 多模型训练工作区

这个目录用于赛题五的多代 LightGBM 训练、比较和产物管理。

## 最终训练与比较区间

- 训练：2018-01-02 至 2023-12-31
- 验证或诊断：2024-01-01 至 2024-12-31；旧代用于早停，新滚动协议只用于最终诊断
- 测试：2025-01-02 至 2026-06-08

每一代运行都从全新的 `LGBMRegressor` 开始，不加载任何前代模型。只有显式传入 `init_model` 才会继续训练，本项目代码始终使用 `init_model=None`。

## 目录结构

```text
train/
├── train_models.py             # 主训练器：先展示参数，再等待确认
├── reporting.py                # 重建累计报告
├── walkforward.py              # 时间协议、标签边界、官方口径指标
├── walkforward_run.py          # 确认后执行三折与最终模型训练
├── 模型训练总报告.md            # 所有已完成模型的同一份报告
├── 模型训练总报告.txt           # 手机阅读和微信传输用纯文本报告
├── configs/                    # 每代模型的 JSON 参数
├── runs/                       # 每次训练的独立目录
│   └── 模型名_时间戳/
│       ├── config_snapshot.json
│       ├── model.txt
│       ├── validation_predictions.csv
│       ├── submission.csv
│       ├── feature_importance.csv
│       ├── data_manifest.json
│       ├── data_*_sample.csv
│       └── summary.json
├── data/                       # 可放置额外数据快照
├── models/                     # 预留模型汇总目录
└── logs/                       # 预留日志目录
```

源始 CSV 保持在 `D:\competition\赛题五数据`。训练器对路径做白名单校验，只接受 `训练集.csv` 和 `测试集_X.csv`，并通过 `usecols` 只读取题目字段；代码没有网络请求或外部数据接口。每次运行会在本代目录保存数据来源清单、字段清单和训练/验证/测试样本快照，不重复复制近 GB 级原始 CSV。

## 第一次运行

当前已准备第一代配置：

```powershell
python train_models.py --config configs\model_001_raw_baseline.json
```

程序会先打印：

- 模型名称；
- 特征模式；
- 数据路径；
- 固定日期切分；
- 全部 LightGBM 参数；
- 保存选项。

程序会要求输入配置中的确认口令。只有输入完全一致的口令才会读取大文件并开始训练。没有确认时不会创建模型。

## 创建下一代模型

复制上一份配置并修改 `model_name`、`confirmation_token` 和需要比较的参数：

```powershell
Copy-Item configs\model_001_raw_baseline.json configs\model_002_more_regularization.json
```

建议一次只改变一组参数。示例：

```json
{
  "model_name": "model_002_more_regularization",
  "confirmation_token": "CONFIRM_MODEL_002",
  "feature_mode": "raw",
  "model_params": {
    "objective": "regression",
    "n_estimators": 3000,
    "learning_rate": 0.03,
    "num_leaves": 31,
    "min_child_samples": 500,
    "reg_lambda": 20.0,
    "colsample_bytree": 0.8,
    "n_jobs": -1,
    "random_state": 42
  }
}
```

训练完成后，程序会自动更新 `模型训练总报告.md` 和 `模型训练总报告.txt`。TXT 使用 UTF-8 BOM 编码、纯文本单行段落，适合通过微信文件传输助手发送到手机阅读；两份报告都会包含本代方法、参数、验证结果、前代差异和产物路径。

第三代参考论文增加中期动量对照：

```powershell
python train_models.py --config configs\model_003_momentum_skip.json
```

`technical_momentum_skip` 在第二代技术特征基础上增加 120/240 日动量，
以及跳过最近 5 个交易日的 20/60/120/240 日动量和对应横截面排名。所有窗口
都按股票和日期升序计算，只使用当前及历史行；两篇论文仅作为研究参考，不会
被读取为训练数据。

## 比较模型

以累计报告中的三个比赛指标为主：

- Rank IC：越高越好；
- 年化 Top1 超额收益：越高越好；
- 平均预测换手率：越低越好。

综合得分为：

```text
Rank IC × 40% + 年化超额收益 × 30% + (1 - 平均换手率) × 30%
```

RMSE 和 MAE 只作为辅助指标。

## 新方案 三折历史扩展窗口加最终诊断

旧配置继续兼容固定切分。新候选使用扩展窗口，并将早停区间与外层评估区间分开：

| 折 | 内层训练 | 内层早停 | 从零重训历史 | 外层评估 |
|---|---|---|---|---|
| 2021 | 2018-01-02 至 2020-06-30 | 2020-07-01 至 2020-12-31 | 2018-01-02 至 2020-12-31 | 2021-01-01 至 2021-12-31 |
| 2022 | 2018-01-02 至 2021-06-30 | 2021-07-01 至 2021-12-31 | 2018-01-02 至 2021-12-31 | 2022-01-01 至 2022-12-31 |
| 2023 | 2018-01-02 至 2022-06-30 | 2022-07-01 至 2022-12-31 | 2018-01-02 至 2022-12-31 | 2023-01-01 至 2023-12-31 |

日期是名义区间，实际以提供数据中的交易日为准。每个训练阶段排除标签兑现日到达下一阶段的样本。评估期末标签若超出本期或未知，只剔除该标签，不改变当日可交易股票集合。

每折先早停选轮数，再使用新模型重训，共六次拟合。最终轮数使用三折内层最佳轮数的中位数，在 2018—2023 年合规历史上进行第七次拟合。2024 年只计算最终诊断指标，不能参与新候选早停；它此前已经被查看，不能称全新盲测。此次不自动把 2024 年标签加入最终训练。

候选 004 使用原始八个字段；候选 005 使用第二代的技术特征。两者沿用旧代超参数，仅改变评估训练流程。每个候选七次独立拟合，分别确认；两者都运行合计十四次。所有拟合均不加载旧权重，运行中会再次打印各阶段实际参数。

参数预览不会读取大 CSV、创建运行目录或启动模型：

```powershell
python train_models.py --config configs\model_004_raw_walkforward.json --preview
python train_models.py --config configs\model_005_technical_walkforward.json --preview
```

训练时省略 --preview，逐个候选输入对应口令。确认授权范围为该候选预先列明的七次拟合和选轮规则。旧的 CONFIRM_MODEL_001 不授权新候选。

新报告按评估协议分组，列出各折得分、三折均值、最差折、ICIR、月度和季度指标。不同选轮方法或标签边界口径的结果不能直接宣称提升。测试 X 仅在三折和 2024 诊断结束后读取并生成预测；无测试 Y，因此不报告测试集真实成绩。

## 自动补充模拟组合业绩归因报告

`reporting.py` 每次重建报告时调用 `portfolio_attribution.py`，为已完成模型的每个历史评估折和最终诊断期增加组合收益、成本、Sharpe、IR、跟踪误差和单基准 Alpha/Beta 归因。原有官方评分保留不变；不加载模型或启动训练。

规则与假设保存在 `configs/portfolio_report.json`，中文说明见 `组合业绩归因说明.txt`。默认每天等权选择预测前10%的纯多头组合。仅使用题目提供训练CSV的当日价格、成交量和保存的涨停标记筛选；股票的未来标签或标签缺失情况不能参与持仓选择。

无风险年利率2%、单边费用万分之三、252个交易日均为情景假设。基准为提供样本内同口径股票的等权毛收益，不下载沪深300、利率或其他外部数据。成本按目标权重变动估算，含建仓，未模拟漂移、冲击与完整成交约束；不能据此宣称可执行实盘收益。

收益缺失时不补零、不重选股票。只对组合与基准收益均完整的共同日期计算配对样本指标，并披露覆盖率；如存在缺口，完整区间复利收益、连续净值和最大回撤不输出数值。Alpha为历史单基准回归截距，不自动等同真实选股能力。

新增产物在 `reports/portfolio/运行名/阶段/内容指纹/`，包含 `attribution.json`、`daily_portfolio.csv` 和 `holdings.csv`。输入、代码或假设改变会使用新内容指纹；不修改已有模型、原始预测和训练摘要。MD与UTF-8 BOM纯文本TXT会同时更新。

仅补充报告的命令为 `python reporting.py --workspace D:\competition\train`。此命令不训练；新增模型仍必须先展示参数并获得对应确认口令。

## 金融逻辑优先及第006代候选

从本次审查起，新训练还必须通过 `financial_logic.py` 门禁。`--preview` 会在训练参数前后同时展示逐项金融假设、预期换手影响、失效风险和完整剔除清单；金融逻辑登记指纹改变时，旧确认配置自动失效。没有登记记录的旧配置只可预览、读取历史结果，不能启动新的拟合。

本次审查对象为最新完成的 `model_003_momentum_skip`。重要性按其 `feature_importances_` 默认的 split 分裂次数排序，并另外保留 gain。Top10中九项缺少原始逐项金融机制注释，先隔离；可事后提出假设不等于已存在事前研究。额外暂时移除原始水平变量、短窗口近似替代项和被隔离源特征的排名版本。

`configs/model_006_financial_logic_v1.json` 从已有50项中保留24项，不增加特征，沿用003的LightGBM超参数，采用三折历史滚动验证和2024最终诊断。完整待确认说明为 `第006代金融逻辑与训练参数待确认.txt`，确认口令是 `CONFIRM_MODEL_006_FINANCIAL_LOGIC`，仅授权该候选列明的7次独立拟合。

第006代与旧003的评估流程不同，因此历史对照不能被解释为只删除特征的因果实验。新的同协议控制候选仍须先登记金融假设、展示参数并单独确认。当前没有新训练结果，不提前判断IC或换手率会改善。

`金融逻辑特征白皮书.txt` 与累计总报告自动同步。每个新运行还保存 `financial_logic_snapshot.json`，记录当次训练前展示的逻辑和风险；每次实际拟合再次打印特征逻辑及有效参数。旧模型只能用于只读审计重要性，禁止把其权重或预测作为新训练输入。
